## 一、选题汇报中提到的参考项目，可以抄什么？

### 1. Memos —— 便签模块的直接参考

Memos 是 Go + React（TypeScript + Tailwind）开发的轻量级备忘录系统，MIT 协议，GitHub 上有超过 59,000 颗星，非常成熟。

**可以直接抄的内容：**

- **便签的 CRUD 逻辑**：Memos 的便签模型已经非常完善（`memo_id, content, visibility, tags, created_ts`），你可以直接参考它的数据库表结构。
- **时间线 UI 布局**：Memos 是“时间线优先”的设计，和你 SRS 中的“动态时间线”高度一致，可以直接参考它的前端布局和交互。
- **分享功能**：Memos 支持公开/私密便签和一键生成分享链接，逻辑完整。

**建议借鉴的模块：** 便签创建、时间线展示、分享链接生成、标签系统。

**⚠️ 注意**：Memos 后端是 Go，如果你们团队不熟悉 Go，可以只参考它的**前端代码**（React + TypeScript）和**数据模型设计**，后端用你们熟悉的 Node.js/Spring Boot 重新实现，工作量仍然可控。

---

### 2. Blinko —— 卡片式笔记前端参考

Blinko 是 Next.js + TypeScript + Tauri + Prisma 构建的，强调卡片式布局和快速记录。

**可以直接抄的内容：**

- **卡片式布局**：如果你们希望便签以卡片网格形式展示，Blinko 的前端组件可以参考。
- **Markdown 编辑器集成**：Blinko 支持 Markdown 编辑器与实时预览，前端代码可直接复用。

**建议借鉴的模块：** 卡片视图布局、Markdown 编辑器集成。

**⚠️ 注意**：Blinko 强调 AI 搜索功能，这部分与你们 MVP 无关，但卡片式 UI 对“便签转知识页面”的展示方式有参考价值。

---

### 3. Super Productivity —— 任务管理和看板的完整参考

Super Productivity 是一个 Angular + Electron 开发的桌面端任务管理工具，GitHub 上超过 16,000 颗星，专注于时间追踪、番茄钟和看板管理。

**可以直接抄的内容：**

- **看板模块（Kanban）** ：版本 12.0 正式支持看板工作流，包括“待办”“进行中”“已完成”等列的定义和拖拽逻辑。你们可以直接参考它的**前端拖拽实现**（Angular 的拖拽逻辑换成 Vue 的 `drag-and-drop` 库即可）。
- **任务数据模型**：Super Productivity 的任务模型包含 `title, status, priority, dueDate, estimatedMinutes` 等字段，与你们 SRS 中的 FR-017~FR-023 高度吻合。
- **番茄钟功能**：内置番茄钟计时器和倒计时界面，可以直接参考其前端实现。

**建议借鉴的模块：** 任务看板拖拽、任务数据模型、番茄钟计时器。

**⚠️ 注意**：Super Productivity 是桌面端应用（Electron），你们只需要它的**任务管理逻辑**和**UI 布局参考**，不需要整体移植。

---

### 4. Obsidian / Logseq —— 双向链接的核心机制参考

Obsidian 是闭源的，但 Logseq 是完全开源的（AGPL-3.0），GitHub 上超过 35,000 颗星，核心理念是双向链接和大纲笔记。

**可以直接抄的内容：**

- **双向链接语法**：Logseq 使用 `[[页面标题]]` 的语法建立链接，与你们 SRS 中的设计完全一致。可以参考它的**链接解析逻辑**。
- **反向链接展示**：Logseq 在页面底部自动展示“反向链接”列表，UI 设计和交互可直接借鉴。
- **笔记内容转任务**：Logseq 支持将 TODO 状态直接嵌入笔记内容（`TODO 某任务`），这个逻辑你们可以直接复用。

**建议借鉴的模块：** 双向链接解析、反向链接展示、笔记内嵌任务。

## 二、还有哪些更直接“缝合”的项目可以参考？

你们的选题非常特殊——它是一个“复合功能”的产品（便签+知识管理+任务+记忆卡片）。如果想要更直接的参考，可以看看这些项目：

### 1. AppFlowy —— Rust + Flutter，Notion 的开源替代品

AppFlowy 是完全开源的（AGPLv3），GitHub 上超过 50,000 颗星，定位是“Notion 的开源替代品”。虽然它的技术栈是 Rust + Flutter，对你们来说迁移成本很高，但它的**功能模块划分**非常值得学习：

- 便签/文档模块
- 看板模块（Kanban Board）
- 数据库模块
- 双向链接支持

你们可以参考 AppFlowy 的**功能架构**和**数据模型设计**，而非代码本身。

### 2. Logseq —— 最接近你们“知识图谱”需求的开源项目

Logseq 的“本地优先”和“大纲笔记”理念与你们非常接近。Logseq 还内置了 PDF 标注和任务管理功能，可以帮你们思考“知识文档如何转化为任务”的流程设计。

### 3. Kylrix —— 一个较小但功能贴近的开源项目

Kylrix 是一个加密的、本地优先的生产力套件，支持“创建笔记→附加到任务→分配给朋友”的完整流程。虽然知名度不高，但它的功能流与你 SRS 中的“便签 → 知识 → 任务”流程非常吻合。

### 4. Odoo Project —— 企业级的项目管理模块参考

Odoo 是一个企业级开源 ERP 系统，但它的 **Project 模块**（任务、看板、甘特图）是完全开源的，可以参考它的任务状态机设计和 API 结构（Python 栈）。

## 三、4人团队的使用策略（重点！）

**原则：不是要“抄”整个项目，而是“借”它们的轮子。**

### 策略一：拆解功能，每个成员认领一个参考源

| 成员  | 主要负责模块        | 参考项目           | 具体内容                                     |
| ----- | ------------------- | ------------------ | -------------------------------------------- |
| 成员A | 便签模块 + 分享     | Memos              | 数据库表结构 + 前端时间线组件 + 分享链接生成 |
| 成员B | 知识模块 + 双向链接 | Logseq             | `[[链接]]` 解析逻辑 + 反向链接展示           |
| 成员C | 任务模块 + 看板     | Super Productivity | 任务数据模型 + 看板拖拽 + 番茄钟界面         |
| 成员D | 前端整合 + 后端 API | 结合以上           | 统一状态管理 + REST API 设计 + 认证模块      |

### 策略二：MVP 阶段只“抄”最容易的，复杂模块自己简化

根据你们 SRS 中 v1.0 MVP 的范围（FR-001~FR-016, FR-040~FR-042），MVP 中难度较大的模块有：

| 模块                            | 难度 | 策略                                                         |
| ------------------------------- | ---- | ------------------------------------------------------------ |
| 便签 CRUD + 时间线              | 低   | 直接参考 Memos                                               |
| 便签转知识页面                  | 低   | 自写，逻辑简单                                               |
| 双向链接（含反链查询）          | 中高 | 参考 Logseq 的数据结构（link 表），先做 1 对 1 链接          |
| 知识图谱可视化（FR-014~FR-015） | 高   | **降低预期！** 先做简易版：用 ECharts 做最基本的节点-边图，仅显示当前页面的直接链接，不追求全局图谱 |
| 用户认证                        | 低   | JWT + bcrypt 自写                                            |

**一句话建议**：在 MVP 阶段（6月13日截止）把“双向链接”做简单一些（比如在知识页面底部只展示“反链列表”，不做拖拽式的复杂可视化），优先保证核心流程跑通。

### 策略三：利用现有生态，减少前端工作量

- **UI 组件库**：推荐 Ant Design Vue 或 Element Plus，可以直接用它们现成的弹窗、标签、表格组件，不需要写 CSS。
- **Markdown 编辑器**：使用 Vditor、ByteMD 或 Milkdown 等开源库，直接集成，避免自己实现 Markdown 解析。
- **双向链接选择器**：可以使用 `fuse.js` 或 `flexsearch.js` 做前端模糊搜索，参考 Memos 的实现方式（输入 `[[` 时弹出选择框）。

## 四、总结：可行性评估与时间预估

| 模块                       | 可复用比例                    | 自写比例                  | 预估时间（人日） |
| -------------------------- | ----------------------------- | ------------------------- | ---------------- |
| 便签模块                   | 70%（Memos直接参考）          | 30%（适配自己的数据模型） | 2-3              |
| 知识管理（含双向链接基础） | 50%（Logseq结构参考）         | 50%（自写前后端实现）     | 3-4              |
| 任务+看板                  | 60%（Super Productivity参考） | 40%（适配后端逻辑）       | 3-4              |
| 用户认证                   | 20%（标准JWT流程）            | 80%                       | 1-2              |
| 前端整合                   | 30%（UI库 + 组件组合）        | 70%                       | 3-4              |
| 部署/文档/测试             | 0%                            | 100%                      | 2                |

**总计**：约 14-19 人日，4 人团队 5-7 天可以完成 MVP 核心功能。

你们只需要**选择性借鉴**这些开源项目的**数据模型、前端组件和业务逻辑**，4人团队完全可以在两周内完成可运行的 MVP 系统。不需要害怕，直接开工就好。
