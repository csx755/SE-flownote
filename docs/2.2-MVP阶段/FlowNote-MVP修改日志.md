## v1.1-MVP 修改摘要

本次修改的核心原则是：优先保证 FlowNote 的核心价值闭环跑通，减少“镀金”功能，提前安排真实用户反馈和交付材料整理。

核心闭环调整为：

```text
碎片便签捕获 → 知识页面结构化 → 任务看板执行 → 用户反馈验证
```

| 原 Feature | 新优先级 | 修改原因 |

| F-028 页面归档与恢复 | P2 | 非核心操作，优先级低 |
| F-029 前端整体 UI 优化 | P2 | 只保留必要可用性优化，避免过度打磨 |
| F-035 性能测试 | P2 | MVP 数据量小，先做基础可用性验证 |

## 四、Sprint 计划修改

### 原计划

```text
Sprint 0 (6/1-6/5)   基础设施搭建 + 系统设计
Sprint 1 (6/6-6/13)  核心功能 MVP
Sprint 2 (6/14-6/22) 功能完善 + 集成联调
Sprint 3 (6/23-6/30) 测试修复 + 交付准备
```

### 修改后

```text
Sprint 0 (6/1-6/2)   范围收缩 + 基础设施
Sprint 1 (6/3-6/7)   便签捕获 + 知识页面结构化
Sprint 2 (6/8-6/10)  任务执行闭环 + 联调冻结
Sprint 3 (6/11-6/13) 用户反馈 + Bug 修复 + 交付材料
```

主要变化：

- Sprint 0 缩短，避免前期设计过重。
- Sprint 1 聚焦便签和知识页面，不混入图谱、番茄钟、记忆卡片。
- Sprint 2 只做任务闭环和联调，不新增大功能。
- Sprint 3 重点从“继续开发”转为“真实反馈和提交材料”。

## 五、数据模型修改

### 5.1 MVP 必需模型

MVP 阶段建议只保留以下核心模型：

- User
- Note
- KnowledgePage
- Task

### 5.2 可选模型

时间允许时再加入：

- Tag

### 5.3 后置模型

以下模型后置到 v1.1 或更晚版本：

- BidirectionalLink
- Board/BoardColumn 的复杂结构
- MemoryCard
- PomodoroRecord

说明：

- 任务看板在 MVP 中可以先通过 Task.status 实现三列视图，不必一开始引入完整 Board/BoardColumn。
- 知识页面之间的复杂链接可以先使用 Markdown 普通链接替代。
- 记忆卡片和番茄钟不参与 6月13日核心价值验证。

## 七、验收标准修改

### 原验收倾向

原计划包含 12 个功能验收项和多个非功能指标，例如知识图谱、番茄钟、记忆卡片、全局搜索、性能测试等。

### 修改后 MVP 验收标准

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| AT-MVP-01 | 用户认证 | 注册、登录、退出正常，用户数据隔离 |
| AT-MVP-02 | 便签管理 | 创建、编辑、归档/删除、时间线展示正常 |
| AT-MVP-03 | 便签转知识页面 | 一键转换成功，内容完整保留 |
| AT-MVP-04 | 知识页面编辑 | Markdown 编辑、预览、保存正常 |
| AT-MVP-05 | 便签转任务 | 一键转换成功，任务出现在待办列 |
| AT-MVP-06 | 任务看板 | 任务能在待办、进行中、已完成之间流转 |
| AT-MVP-07 | 可运行部署 | README 或部署文档可指导他人启动系统 |
| AT-MVP-08 | 基础测试 | 核心流程测试可运行并通过 |
| AT-MVP-09 | 用户反馈 | 至少 3 名真实用户反馈，包含联系方式和原始记录附件 |

## 十、修改结论

本次修改不是降低项目目标，而是让 FlowNote 更符合 MVP 评价标准：

- 对“核心价值验证”更有利：用户能真实体验完整闭环。
- 对“工程实践与代码质量”更有利：减少半成品功能，集中测试核心流程。
- 对“需求分析与决策质量”更有利：清楚说明 P0/P1/P2 和后置原因。
- 对“用户反馈质量”更有利：提前冻结试用版本，给反馈收集留出时间。
- 对“文档质量”更有利：交付物和课程要求一一对应。

最终建议：6月13日前只围绕 P0 功能推进，任何 P1/P2 功能都不能影响核心闭环稳定性和反馈材料完整性。
