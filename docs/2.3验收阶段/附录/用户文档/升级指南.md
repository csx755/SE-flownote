**每次升级前必须备份！**

```bash
docker exec flownote-db pg_dump -U flownote flownote > backup_$(date +%Y%m%d_%H%M%S).sql
```

验证备份：

```bash
head -20 backup_*.sql   # 应看到 PostgreSQL SQL 语句
```

### 2.2 确认当前版本

```bash
git log --oneline -1   # 查看当前 HEAD commit
pnpm --filter @flownote/api test   # 确认测试通过
```

## 三、标准升级流程

### 方式一：Git 拉取升级（推荐）

适用于拉取新版本代码进行升级。

```bash
# 1. 停止运行中的服务（Ctrl+C 或 kill 进程）

# 2. 备份数据库
docker exec flownote-db pg_dump -U flownote flownote > backup_$(date +%Y%m%d_%H%M%S).sql

# 3. 拉取最新代码
git fetch origin
git checkout <目标分支或标签>

# 4. 安装新依赖（如有）
pnpm install

# 5. 应用数据库变更
pnpm db:push
# 输出 [✓] Changes applied 表示有表结构变更
# 输出 [i] No changes detected 表示无变更

# 6. 运行测试确认
pnpm --filter @flownote/api test

# 7. 重新启动服务
pnpm dev
```

### 方式二：Docker Compose 升级

```bash
# 1. 备份数据库（同上）

# 2. 拉取代码
git pull

# 3. 重新构建并启动
docker compose up -d --build

# 4. 应用数据库变更
pnpm db:push
```

## 四、各版本升级注意事项

### 从 v1.0-MVP 升级到 v1.1

v1.1 新增了 **标签系统** 和 **反向链接**。

**数据库变更：**
- 新增 `tags`、`note_tags`、`page_tags`、`task_tags` 四张表

**升级步骤：**

```bash
# 标准流程即可，db:push 会自动创建新表
pnpm db:push
```

**破坏性变更：**
- 无。所有 v1.0 数据和 API 保持不变。

**验证：**
1. 登录后应能在便签/知识页/任务中看到标签选择器
2. 顶部导航栏出现搜索图标
3. 知识页编辑页底部出现反向链接区域

---

### 从 v1.1 升级到 v1.2

v1.2 新增了 **任务筛选排序**、**统计面板**、**文件夹管理**、**导入导出**、**Markdown 增强**。

**数据库变更：**
- `notes`、`knowledge_pages`、`tasks` 表新增 `folder` 列（varchar 255）

**API 路由变更：**
- 新增 `GET /api/v1/folders?type=` 文件夹列表
- `GET /api/v1/tasks` 新增 `priority`、`sortBy`、`order` 查询参数
- `GET /api/v1/tasks/stats` 任务统计（注意：`/stats` 路由必须在 `/:id` 之前）
- `GET /api/v1/pages/export/:id` 导出功能（注意：必须在 `/:id` 之前）
- `POST /api/v1/pages/:id/convert-to-task` 页面转任务

**升级步骤：**

```bash
# 标准流程
git pull
pnpm install
pnpm db:push     # 新增 folder 列
pnpm --filter @flownote/api test
pnpm dev
```

**破坏性变更：**
- 无。folder 列为可空，已有数据不受影响。

**前端变更：**
- 知识页列表新增左侧文件夹树
- 任务看板新增状态/优先级筛选 + 排序
- 任务详情页新增 Markdown 预览切换
- 知识页编辑页新增导入/导出/转任务按钮

**验证：**
1. 知识页列表左侧显示文件夹侧栏
2. 任务看板顶部显示统计面板（总计/待办/进行中/已完成/逾期）
3. 任务看板筛选栏有状态和优先级下拉框
4. 任务详情页描述区有"编辑/预览"切换按钮

## 五、数据库迁移详解

FlowNote 使用 **Drizzle Kit** 管理数据库 schema。

### 查看迁移状态

```bash
pnpm db:push   # 显示 pending changes
```

### 回滚数据库

```bash
# 使用备份恢复
docker exec -i flownote-db psql -U flownote flownote < backup.sql
```

### 手动执行 SQL

```bash
docker exec -it flownote-db psql -U flownote -d flownote
```

```sql
-- 示例：手动添加列
ALTER TABLE notes ADD COLUMN folder VARCHAR(255);
ALTER TABLE knowledge_pages ADD COLUMN folder VARCHAR(255);
ALTER TABLE tasks ADD COLUMN folder VARCHAR(255);
```

## 七、常见升级问题

### Q1：`pnpm db:push` 报错

**原因**：数据库连接失败或 schema 定义有冲突。

**解决：**
```bash
# 确认 PostgreSQL 在线
docker ps | grep flownote-db

# 确认 .env 配置正确
cat apps/api/.env

# 查看详细错误
pnpm --filter @flownote/api exec drizzle-kit push --verbose
```

### Q2：升级后前端白屏 / 报错

**原因**：依赖未更新或 Nuxt 缓存问题。

**解决：**
```bash
rm -rf apps/web/.nuxt apps/web/node_modules/.cache
pnpm install
pnpm dev
```

### Q3：升级后 API 返回 500

**原因**：数据库 schema 未同步。

**解决：**
```bash
pnpm db:push
# 如果仍然失败：
docker exec -it flownote-db psql -U flownote -d flownote
# 手动检查表结构：
\dt
\d notes
\d knowledge_pages
\d tasks
```

### Q4：端口冲突（EADDRINUSE）

```bash
npx kill-port 3000
# 或
npx kill-port 3001
```

### Q5：升级后登录失败

**原因**：`JWT_SECRET` 被修改导致旧 token 失效。

**解决**：重新登录即可，数据不受影响。

### 生产环境升级命令

```bash
# 1. 进入维护模式（通过 Nginx 或通知用户）

docker exec flownote-db pg_dump -U flownote flownote > /backup/pre_upgrade_$(date +%Y%m%d_%H%M%S).sql

cd /opt/flownote
git fetch origin
git checkout <版本标签>

# 7. 退出维护模式
```

## 九、回滚方案

如果升级后出现严重问题：

```bash
# 1. 切回旧版本代码
git checkout <旧版本commit或标签>

# 2. 恢复数据库
docker exec -i flownote-db psql -U flownote flownote < backup.sql

# 3. 重新构建/启动
docker compose up -d --build
# 或
pnpm dev

# 4. 验证
curl http://localhost:3000/health
pnpm --filter @flownote/api test
```
